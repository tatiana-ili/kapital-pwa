# Настройка Supabase для одного пользователя

## 1. Создайте проект

Создайте личный проект Supabase в подходящем регионе. Пароль базы данных сохраните в менеджере паролей — он не используется во frontend и не должен попадать в Git.

## 2. Создайте таблицы и защиту

В SQL Editor проекта по порядку выполните:

1. `supabase/migrations/202609110001_initial_schema.sql` — таблицы PostgreSQL и Row Level Security;
2. `supabase/migrations/202609110002_statement_import.sql` — атомарное сохранение проверенной выписки;
3. `supabase/migrations/202609120003_import_integrity.sql` — повторный импорт с учётом счёта, совместимость старых отпечатков и связывание подтверждённых внутренних переводов;
4. `supabase/migrations/202609120004_category_management.sql` — направления правил, проверка имён категорий и атомарное переименование в операциях, правилах и бюджетах;
5. `supabase/migrations/202609160001_category_rule_all_fields.sql` — поиск правил по всем полям операции.

Персональные строки ограничены условием `user_id = auth.uid()`.

`supabase/seed.sql` содержит только синтетические данные и нужен лишь для отдельной проверки схемы. Для личного профиля запускать его необязательно.

## 3. Создайте единственного пользователя

В разделе Authentication создайте пользователя с личным email и отдельным паролем приложения. Это не должен быть пароль от банка. Подтвердите пользователя и отключите открытую самостоятельную регистрацию, пока приложение предназначено для одного человека.

## 4. Подключите frontend

Скопируйте `.env.example` в `.env.local` и заполните два публичных значения из настроек Supabase:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-public-anon-or-publishable-key
```

Anon/publishable key предназначен для браузера и безопасен только вместе с включённым RLS. Service-role key приложению не нужен и запрещён во frontend.

## 5. Проверьте

Перезапустите `pnpm dev`, откройте `/login` и войдите созданным email и паролем приложения. Затем проверьте `/categories`: создайте свою категорию и правило. На `/import` выберите выписку, проверьте категории и подтвердите операции. После сохранения счёт и операции появятся на главной странице.

Перед публикацией выполните `pnpm test` и `pnpm build`. Значения `NEXT_PUBLIC_*` в статической сборке фиксируются во время build, поэтому после изменения `.env.local` приложение необходимо пересобрать и опубликовать заново.
