# Капитал

Mobile-first PWA для контроля личных финансов по выпискам Т-Банка, Сбера, Яндекс Банка и Ozon Банка. Этап 1 включает Dashboard, Transactions, Next.js App Router, Supabase/PostgreSQL, авторизацию и PWA-оболочку. Этап 2 добавляет ручной импорт CSV, XLSX и текстовых PDF. Этап 3 добавляет собственные категории и правила автоматической категоризации.

Приложение не подключается к банкам, не запрашивает банковские логины, пароли или SMS-коды и не выполняет платежи. Выписка разбирается локально в браузере; в базу попадают только подтверждённые нормализованные операции, а исходный файл не загружается.

## Запуск

```bash
pnpm install
pnpm dev
```

Откройте `http://localhost:3000`. Без `.env.local` приложение работает в явно обозначенном деморежиме.

Экран `/import` принимает CSV, XLSX и PDF до 20 МБ. Для проверки без личных данных используйте `public/examples/kapital-demo-statement.csv`. Импорт определяет банк, предлагает сопоставление колонок и запоминает подтверждённый профиль для следующей выписки того же формата. В деморежиме операции и профиль хранятся только в `localStorage` текущего браузера.

На `/categories` можно создавать и переименовывать категории, добавлять правила по продавцу или описанию, выключать и удалять правила. После ручной смены категории в операции или предпросмотре импорта приложение предложит сохранить правило для следующих выписок. Системные категории нельзя переименовать. Демоданные и настройки сохраняются только в текущем браузере.

## Подключение Supabase

Для защищённого режима создайте собственный проект Supabase и выполните инструкцию [docs/supabase-setup.md](docs/supabase-setup.md). В репозитории хранится только безопасный шаблон `.env.example`; локальный `.env.local` исключён из Git.

После подключения Supabase:

- все экраны требуют входа;
- пользователь видит только свои строки благодаря Row Level Security;
- Dashboard читает счета и операции из PostgreSQL;
- изменение категории и аналитических признаков операции сохраняется в базе;
- собственные категории и правила сохраняются в PostgreSQL с RLS;
- импорт выписки атомарно создаёт счёт, операции, снимок остатка и запись аудита;
- отпечатки операций и проверка повторного файла учитывают счёт; подтверждённые стороны внутреннего перевода связываются при однозначном совпадении;
- выход завершает Supabase-сессию.

## Проверка

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

Production build создаётся в `out/` и публикуется как статическая PWA. Service worker кеширует только статические файлы и никогда не сохраняет навигационные страницы, API-ответы или ответы Supabase.

Полное техническое задание и план этапов сохранены в [docs/technical-spec.md](docs/technical-spec.md). Архитектурные решения, контракт будущих импортёров и риски описаны в [docs/architecture.md](docs/architecture.md).
