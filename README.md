# Капитал

Mobile-first PWA для контроля личных финансов по выпискам Т-Банка, Сбера, Яндекс Банка и Ozon Банка. Этапы 1–5 включают Dashboard, операции, импорт CSV/XLSX/PDF, категории и правила, аналитику, бюджеты, подписки и финансовые цели.

Приложение не подключается к банкам, не запрашивает банковские логины, пароли или SMS-коды и не выполняет платежи. Выписка разбирается локально в браузере; в базу попадают только подтверждённые нормализованные операции, а исходный файл не загружается.

## Запуск

```bash
pnpm install
pnpm dev
```

Откройте `http://localhost:3000`. Без `.env.local` приложение работает в явно обозначенном деморежиме.

Экран `/import` принимает CSV, XLSX и PDF до 50 МБ. Для проверки без личных данных используйте `public/examples/kapital-demo-statement.csv`. Текстовые PDF Т-Банка, Сбера и Яндекс Банка разбираются отдельными координатными парсерами: многострочные описания объединяются, для Сбера учитывается отсутствие минуса у списаний, а суммы сверяются с контрольными итогами и остатками выписки. При успешной сверке ручное подтверждение PDF не требуется; приложение показывает только неоднозначные операции. Скан или обезличенная PDF-копия без текстового слоя отклоняется без сохранения неполных данных. В деморежиме операции и профиль хранятся только в `localStorage` текущего браузера.

На `/categories` можно создавать и переименовывать категории, добавлять правила по продавцу или описанию, выключать и удалять правила. После ручной смены категории в операции или предпросмотре импорта приложение предложит сохранить правило для следующих выписок. Системные категории нельзя переименовать. Демоданные и настройки сохраняются только в текущем браузере.

На `/budget` задаются лимиты по категориям и месяцам. Прогресс использует все доступные операции за выбранный месяц, исключая внутренние переводы и скрытые из аналитики строки. На `/subscriptions` приложение предлагает регулярные платежи из подходящих категорий после трёх похожих списаний с близкой суммой и интервалом; найденное можно уточнить или пометить как не подписку. На `/goals` задаются сумма, срок и накопленный вручную прогресс; необходимый ежемесячный взнос рассчитывается по оставшейся сумме и сроку. В деморежиме планы хранятся в `localStorage`.

Кнопка поиска в шапке открывает `/search`. Поиск охватывает всю историю операций, принимает продавца, описание, категорию, заметку или точную сумму и показывает найденные строки, расходы, доходы и общий итог. В итогах не учитываются внутренние переводы и скрытые из аналитики операции.

Dashboard показывает историю капитала за 1, 3, 6, 12 месяцев или всё время по сохранённым снимкам остатков. Линия появляется только после того, как известны остатки всех активных счетов; неполную историю приложение не выдаёт за общий капитал. Блок «Наблюдения» сравнивает расходы с теми же днями прошлого месяца и оценивает регулярные платежи по найденным повторам. В карточке операции можно изменить продавца и заметку; исходный отпечаток импорта при этом сохраняется. На `/settings` выбираются светлая, тёмная или системная тема, показан режим хранения данных и доступен выход из учётной записи Supabase.

## Подключение Supabase

Для защищённого режима создайте собственный проект Supabase и выполните инструкцию [docs/supabase-setup.md](docs/supabase-setup.md). В репозитории хранится только безопасный шаблон `.env.example`; локальный `.env.local` исключён из Git.

После подключения Supabase:

- все экраны требуют входа;
- пользователь видит только свои строки благодаря Row Level Security;
- Dashboard читает счета и операции из PostgreSQL;
- изменение категории и аналитических признаков операции сохраняется в базе;
- собственные категории и правила сохраняются в PostgreSQL с RLS;
- бюджеты, подтверждённые и отклонённые подписки, финансовые цели сохраняются в PostgreSQL с RLS;
- импорт выписки атомарно создаёт счёт, операции, снимок остатка и запись аудита;
- отпечатки операций и проверка повторного файла учитывают счёт; подтверждённые стороны внутреннего перевода связываются при однозначном совпадении;
- выход завершает Supabase-сессию.

## Проверка

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

Production build создаётся в `out/` и публикуется как статическая PWA. Service worker кеширует только статические файлы и никогда не сохраняет навигационные страницы, API-ответы или ответы Supabase.

Полное техническое задание и план этапов сохранены в [docs/technical-spec.md](docs/technical-spec.md). Архитектурные решения, контракт будущих импортёров и риски описаны в [docs/architecture.md](docs/architecture.md).
